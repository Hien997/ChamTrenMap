# Issue Tracker Config

How agents read from and write to this project's issue tracker. Referenced by
the `triage` and `code-review` skills. If the tracker changes, update this
file — it is the single source of truth for tracker access.

## Tracker

- **Provider:** GitHub Issues + Pull Requests, operated through the `gh` CLI.
  (GitHub was chosen because this skill suite's conventions are gh-based;
  if the project moves to another tracker, this file is the only place that
  needs rewriting.)
- **Repository:** `OWNER/REPO` — **TODO: fill this in.** The local clone has no
  `origin` remote yet, so it cannot be derived automatically. Until it is set,
  ask the maintainer which repository to operate on before running any command.
  Once a remote exists, derive it with `gh repo view --json nameWithOwner` or
  from `git remote get-url origin`.
- **Prerequisites:** `gh` must be installed and authenticated
  (`gh auth status` shows a logged-in account with access to the repository).
  If `gh` is missing or unauthenticated, stop and tell the maintainer — do not
  fall back to scraping the web UI.

## Label mapping

Canonical triage role → label string in the tracker. This repo uses an
identity mapping: the label string equals the canonical role name.

| Canonical role   | Label string     |
| ---------------- | ---------------- |
| `bug`            | `bug`            |
| `enhancement`    | `enhancement`    |
| `needs-triage`   | `needs-triage`   |
| `needs-info`     | `needs-info`     |
| `ready-for-agent`| `ready-for-agent`|
| `ready-for-human`| `ready-for-human`|
| `wontfix`        | `wontfix`        |

Every triaged issue/PR carries exactly one category label (`bug` or
`enhancement`) and exactly one state label. Create any missing labels before
first use:

```sh
gh label create needs-triage --repo OWNER/REPO --color e99695 --force
```

Suggested colors: `bug` `d73a4a`, `enhancement` `a2eeef`, `needs-triage`
`e99695`, `needs-info` `fbca04`, `ready-for-agent` `0e8a16`,
`ready-for-human` `1d76db`, `wontfix` `ffffff`.

## Reading

```sh
# Discovery — fetch all open issues once, then bucket client-side:
#   unlabeled    = empty `labels` array
#   needs-triage = has the needs-triage label
#   needs-info   = has the needs-info label; flag only when the reporter
#                  commented after the latest triage-notes comment
gh issue list --repo OWNER/REPO --state open --limit 100 \
  --json number,title,labels,createdAt,updatedAt,author

# One item, full context (body, comments, labels)
gh issue view 42 --repo OWNER/REPO --comments

# A PR: same, plus the diff for verification
gh pr view 42 --repo OWNER/REPO --comments
gh pr diff 42 --repo OWNER/REPO
```

Reporter activity since the last triage notes = a comment by the issue author
with a `createdAt` newer than the latest triage-notes comment (triage comments
start with the AI disclaimer below).

## Writing

```sh
gh issue edit 42 --repo OWNER/REPO --add-label ready-for-agent --remove-label needs-triage
gh issue comment 42 --repo OWNER/REPO --body-file /tmp/comment.md
gh issue close 42 --repo OWNER/REPO
gh pr checkout 42   # locally verify a PR's claimed behavior before briefing it
```

Every comment or issue body posted by an agent during triage **must** start
with this disclaimer:

```
> *This was generated by AI during triage.*
```

## External PRs

PRs are a triage request surface: a PR is an issue with attached code, going
through the same triage roles.

**External** = the PR author has no maintainer relationship with the repo —
GitHub `authorAssociation` of `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`,
`FIRST_TIMER`, or `NONE`. Authors with `OWNER`, `MEMBER`, or `COLLABORATOR`
are in-flight internal work and are not surfaced by discovery; an explicitly
named PR is always triaged regardless of author.

```sh
gh pr list --repo OWNER/REPO --state open \
  --json number,title,author,authorAssociation,updatedAt
```
